no local compiler, Instrument design system. Set `MARKETING_VERSION: "1.6"`.

file:line is given it's a pointer from the review — re-read the code, line numbers may be off.

- Race: **Monday June 21, 2027**, a real event: the race date is **fixed**.
- Plan is now 36 weeks + race Monday (week 37). Phases: 1–14 build legs, 15–24 aerobic power,

## A. Plan data and schedule

### A1. New plan file
`MilePace/Resources/plan.json` was regenerated by `scripts/gen_plan.py` (don't hand-edit it).
New top-level fields: `version: 2`, `raceDate: "2027-06-21"`. Sessions may have `targetSeconds`
(time trials 395 / 365 / 345, race 330). 37 weeks, 161 sessions, no sessions on weekday 3 or 7.
- `PlanFile` decodes `version` (default 1 if absent) and `raceDate` (optional);
  `PlanSession` decodes `targetSeconds: Double?`.
- `PlanStore`: persist the plan version alongside progress; if the stored version ≠ file version,
  reset progress (the plan hasn't started yet, so nothing real is lost).
- UI that said "/ 48" or assumed 48 weeks uses `plan.weeks.count`. Phase names/ranges come from
  data (phase numbers on weeks), not hard-coded week numbers. Grep for `48` in Swift sources.
- Update `BundledPlanTests` for 37 weeks, race in week 37 weekday 1, targetSeconds present on all
  timeTrial/race sessions, and no session on weekday 3 or 7 (Wed/Sun).

### A2. Push back that only moves unfinished sessions (replace the shift model)
Replace `PlanShift`-based offsets with per-session overrides:
`PlanProgress.dayOverrides: [String: Int]` (session index → absolute day offset), default `[:]`.
`dayOffset(i) = dayOverrides[i] ?? baseOffset(i)`. Keep decoding old `shifts` (ignore them; the
version reset clears them anyway).

`PlanSchedule.pushingBack(missed m, today t) -> PushBackResult { progress, dropped: [Int] }`:
1. `pending` = indices ≥ m (in plan order) with no status, **excluding the race**.
2. Place them in order. Session m goes to day `t`. Each next pending session goes to
   `max(its current dayOffset, previousPlacedDay + 1)`, then advanced until it lands on an allowed
   day: weekday not Wed (3) / Sun (7), not already occupied by a done session or the race, and not
   a hard session (road/track/timeTrial) the day right after another placed hard session.
   Easy/long can follow hard. Stop moving as soon as a session can keep its current day (and every
   session after it keeps its day too), so a 1-day slip only ripples as far as it must.
3. Any session whose placement lands on or after the race day − 1 (the day before the race must
   stay an easy shakeout or rest) is **dropped**: mark it `.skipped` and return it in `dropped`.
4. The race session never moves.
The missed card text before confirming: "doing it today moves N sessions later" and, if
`dropped` would be non-empty, "and drops M sessions to keep the race on mon jun 21."
(Compute with a dry run of the same function.)

### A3. Old misses auto-skip
On reconcile: any unstatused session whose day is more than 2 days before today
(`dayOffset < today − 2`) becomes `.skipped`. `firstMissed` therefore only returns sessions from
the last 2 days.

### A4. Matching activities (replaces "any activity that day")
`reconciled(activities: [ActivityDay])` where `ActivityDay { day: Int; kind: .run(miles: Double, workoutName: String?) | .track(presetName: String) }`.
- Activity day = the activity's **start** time; anything starting before 03:00 counts for the previous day.
- easy/long: runs that day (without a workoutName) whose total miles ≥ 50% of the session's planned miles.
- road: a run that day whose `workoutName` equals the session's preset name.
- track/timeTrial/race: a track workout that day (any preset; a time trial needs the mile-tt preset).
- Each activity satisfies at most one session; only sessions scheduled that day are considered.
- `RunRecord` gets `var workoutName: String = ""` (default in declaration). Set it on save from the
  run's workout. Stop copying the workout name into notes.
- `WorkoutRecord.date` must be the session **start** time, not save time.

### A5. Active session (stale "start" bug)
- `PlanStore.activeSessionIndex` is cleared when: the user leaves the screen the route opened
  (track setup "back", run idle screen switching modes or tab without starting), the calendar day
  changes, or the app launches. It is only used if the saved activity matches its kind (run → easy/
  long/road; track workout → track/timeTrial/race).
- `completeActive()` is called with the activity kind and ignores mismatches.

### A6. Dates and time zones
Store the plan start as the `"yyyy-MM-dd"` string only; convert to a `Date` in the **current**
calendar/time zone at every computation (`PlanCalendar`). Never cache a `Date` for the start.

### A7. Weekly miles
"this week x / y mi" and the Sunday summary both use the **calendar** Mon–Sun week containing the
day, and count runs plus track workouts estimated as `total rep meters / 1609.344 + 2.0` miles
(warm-up and cool-down). Planned miles = the `PlanWeek.miles` of the plan week that most of that
calendar week's sessions belong to.

## C. Run tracking and audio
1. **Frozen pace** (`PaceCalculator`/`LocationTracker`): `lastSampleAt` updates only when a sample
   was accepted/anchored for distance or produced a Doppler update. If none for > 8 s,
   `currentPace = nil` (shows `--:--`) and the zone guard gets nil (which resets it).
2. **Cadence during pauses**: record pause intervals; at stop, compute average cadence as
   (pedometer steps over the whole run − steps during pause intervals) / moving time, using
   `CMPedometer.queryPedometerData(from:to:)` for the whole run and for each pause interval (this also
   fixes undercounting if live updates stalled while locked). Fall back to the live count if queries fail.
   The "set to my cadence +5%" button uses live cadence excluding paused time (subtract steps
   counted while paused).
3. **Mile cues during workouts**: when a workout session exists and is in rep or recovery, suppress
   the mile announcement too (not just distance cues). Always respect the "announce each mile" toggle.
4. **Pause/resume**: reset the zone guard (and rep guard) on pause and on resume.
5. **Audio**:
   - While the metronome runs, speech uses options `[.mixWithOthers]` only (no ducking), so other
     apps' audio is never left ducked; don't change the session category/options while the engine
     runs except as needed to start/stop it.
   - Without the metronome: ducking as now, but deactivate 0.5 s after the last utterance finishes;
     if `setActive(false)` throws, retry once after 1 s. Log both to Diagnostics.
6. **End of run**: call `Coach.shared.stopSpeaking()` when a run ends (and when a track workout ends).
7. **Headphones**: on `AVAudioSession.routeChangeNotification` with reason `.oldDeviceUnavailable`,
   stop the metronome (and set its toggle off) instead of restarting it.
8. **GPS warm-up timeout**: after the 3-minute auto-stop, the status line shows "gps paused" with a
   `[ wake ]` accessory that restarts warm-up; tapping start always works.
9. **Precise location off**: if `manager.accuracyAuthorization == .reducedAccuracy`, the run idle
   screen shows an inverted warning block "precise location is off. distance and pace won't record."
   with `[ open settings ]`.
10. **Pace guard widening** (`PaceZones`): add `static func guardRange(_ r: ClosedRange<Double>) -> ClosedRange<Double>`
    that widens any range narrower than 10 s to `mid − 5 … mid + 5` (wider ranges unchanged). Use it
    everywhere a range is used for cues, the pace meter, the "on target" verdicts, and the ranges shown
    on run/today screens and in reminders. Goal ranges become ±5. Don't change the anchor table
    (existing PaceZonesTests must pass).

## D. Track timer
1. **Minimum lap**: ignore lap taps < 10 s after the lap/rep started (or after GO); give a light
   haptic and flash "too soon" in the lap block for 1 s.
2. **Undo from results**: the results screen shows `[ undo last tap ]`, returning to the running state
   of the final lap.
3. **Skip rest** pushes an undo snapshot, so undo restores the rest.
4. **Discard** on results needs a second confirming tap (`[ discard ]` → `[ yes, discard ]`), like
   history delete. **Save** is guarded against double taps.
5. **Rest end while locked**: when the app goes to background during a rest, schedule a local
   notification (sound) at the rest end time: "go when ready. rep 4 of 6."; cancel it on return to
   foreground or when the rest ends in the foreground.
6. **Survive being killed**: make the track session state `Codable`; persist it (spec + state +
   splits + timestamps) to UserDefaults on background and on each tap; on next launch, if a saved
   unfinished session exists from the last 3 hours, the track tab shows "resume 6 × 400 @ R?"
   `[ resume ]` / `[ discard ]`. Clear on finish/save/discard.
7. **Time trial targets**: `PlanRoute.track(presetId:targetSeconds:)`. When started from the plan,
   the mile-tt preset uses the session's `targetSeconds` (6:35/6:05/5:45, race 5:30). From the track
   tab directly: target = the current mile time setting.
8. **Goal pace**: derive "@ goal" presets and the "goal …/400" header from `AppSettings.goalMile`
   (no hard-coded 41 / 82.5).
9. **Setup sheet**: changing rep distance rescales the target proportionally; set rest defaults to
   max(set rest, 2 × rep rest) when sets > 1.

## E. Input parsing
- Mile time and goal fields: a bare 3–4 digit number is m:ss (`645` → 6:45, `1005` → 10:05) when
  the last two digits are < 60. Commit on submit / focus loss, not on every keystroke. Valid range
  5:00–8:30; outside → keep the old value and show the note.
- Add miles time: a bare number is **minutes** (`45` → 45:00); `m:ss` and `h:mm:ss` accepted. Reject
  if the resulting pace is outside 4:00–20:00 /mi with a note.
- Put the parsing in pure helpers with tests.
